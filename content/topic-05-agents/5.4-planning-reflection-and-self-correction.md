**Definition**

Planning, reflection, and self correction are techniques that improve agent reliability by adding explicit reasoning steps. Planning asks the agent to write a plan before acting. Reflection asks the agent to review its own work after acting. Self correction asks the agent to retry or revise when something goes wrong.

**Why it matters in delivery**

Naive agents that just react to each step often fail on complex tasks. They get distracted, take inefficient paths, or stop too early. These three patterns are the most reliable ways to lift agent quality without changing the model. They are cheap to add and most production agents use at least one.

**How it works**

| Pattern | What it does | When to use | Cost |
|---|---|---|---|
| Plan first | Agent writes a step by step plan before executing | Multi step tasks, complex goals | One extra LLM call up front |
| Re plan on failure | When a step fails, agent revises the plan | Tasks with unpredictable obstacles | Extra calls on failure paths |
| Reflection after action | Agent reviews its own output, checks for errors | Quality sensitive tasks, final outputs | Doubles cost on reviewed steps |
| Self correction | Agent retries with a different approach when output is wrong | Coding, structured output, recoverable errors | Extra calls per retry |
| Critique by another agent | A second agent reviews the first agent's work | High stakes outputs | Doubles overall cost |

**Worked example**

Without planning, asked to "research Acme's competitive position":

- Agent calls search ("Acme competitors") -> gets generic list
- Agent calls search ("Acme market share") -> gets one stale figure
- Agent generates a thin summary

With planning:

- Agent writes plan: "1. Identify Acme's industry and segment, 2. List top 3 competitors, 3. Find revenue and market share data, 4. Find recent strategic moves, 5. Synthesise comparative position"
- Agent executes plan step by step
- Agent reflects: "Did I address each point?" If not, retries weak steps
- Output is structured, complete, and traceable

**PM decision points**

- Is the task complex enough that planning adds value, or is the agent already reliable without it?
- What is the quality bar that justifies doubling cost via reflection or critique?
- How do we ensure the agent's plan is not just performance theatre but actually guides execution?

**Watch outs**

- Plans can be wrong, the agent should be allowed to deviate, not slavishly follow a bad plan
- Reflection adds latency, in real time use cases it may be unacceptable
- Self correction loops can run indefinitely, always cap retries

**Takeaway: planning, reflection, and self correction are the cheap quality lifts of agentic design. Add them when reliability matters more than cost or speed.**

**Qantas story**

Reflection and planning patterns are particularly valuable in Qantas AI use cases where the cost of getting it wrong is high. Take the disruption recovery agent from earlier. A naive version reacts to each step in isolation and can produce recovery plans that look reasonable but miss critical constraints. Adding planning and reflection transforms the output.

The pattern works as follows. When a disruption is detected, the agent first writes a structured plan: "I will (1) identify all affected flights and downstream rotations, (2) classify each flight by impact, (3) identify constraints (crew duty, aircraft availability, slot rules), (4) propose recovery options per affected flight, (5) verify each option against constraints, (6) rank options by total cost and customer impact, (7) generate a recovery summary." The plan is visible to the operations controller before execution.

The agent then works through the plan. After each major step, a reflection prompt asks "have I addressed everything required by this step, and have I introduced any inconsistencies with earlier steps." The reflection is a separate model call, and it adds latency and cost, but it catches errors that single shot reasoning misses.

At the end, a final reflection asks "is this recovery plan internally consistent, does it respect all constraints, and would I confidently present it to a duty manager." If the reflection identifies issues, the agent revises before presenting.

The cost of this discipline is real. Planning and reflection roughly double the LLM cost per task. The benefit is also real. In high stakes contexts like disruption recovery, the quality lift from these patterns is the difference between a tool that operations controllers trust and one they ignore. Trust is the currency of AI adoption in operational environments.

The interesting failure mode is performance theatre, where the agent writes plans and reflections that look thorough but do not actually shape its behaviour. The agent says "I will check crew duty time limits" and then proceeds to recommend a swap that violates them. The defence is to have plans and reflections produce structured output that downstream code actually validates, not just freeform text that nobody reads.

For AI delivery, the lesson is that planning and reflection are the cheap quality lifts of agentic design. They double cost but often more than double quality on hard tasks. The right framing for clients is to position them as the difference between a draft and a reviewed draft, not as fancy AI patterns. Operations leaders understand the value of reviewed work, and that framing builds trust faster than technical descriptions.

**定义**

规划、反思和自我纠正是通过添加显式推理步骤来提高 agent 可靠性的技术。规划要求 agent 在行动之前写一个计划。反思要求 agent 在行动之后审查自己的工作。自我纠正要求 agent 在出错时重试或修订。

**为何在交付中重要**

仅对每一步反应的天真 agent 经常在复杂任务上失败。它们分心、走低效的路径,或过早停止。这三种模式是在不改变模型的情况下提升 agent 质量的最可靠方式。它们添加便宜,大多数生产 agent 至少使用一种。

**运作原理**

| 模式 | 它做什么 | 何时使用 | 成本 |
|---|---|---|---|
| 先规划 | Agent 在执行前写一步一步的计划 | 多步任务、复杂目标 | 一次额外的 LLM 调用预先 |
| 失败时重新规划 | 当步骤失败时,agent 修订计划 | 带不可预测障碍的任务 | 失败路径上的额外调用 |
| 行动后反思 | Agent 审查自己的输出,检查错误 | 质量敏感的任务,最终输出 | 在审查步骤上成本翻倍 |
| 自我纠正 | 当输出错误时,Agent 用不同方法重试 | 编码、结构化输出、可恢复错误 | 每次重试的额外调用 |
| 另一个 agent 的批评 | 第二个 agent 审查第一个的工作 | 高风险输出 | 整体成本翻倍 |

**举例**

没有规划,被要求"研究 Acme 的竞争位置":

- Agent 调用搜索 ("Acme 竞争对手") -> 得到通用列表
- Agent 调用搜索 ("Acme 市场份额") -> 得到一个过时的数字
- Agent 生成一个薄的摘要

有规划:

- Agent 写计划: "1. 识别 Acme 的行业和细分市场,2. 列出前 3 个竞争对手,3. 找到收入和市场份额数据,4. 找到最近的战略举措,5. 综合比较位置"
- Agent 按计划逐步执行
- Agent 反思: "我是否解决了每一点?"如果没有,重试薄弱的步骤
- 输出是结构化的、完整的,并且可追溯

**PM 决策点**

- 任务是否足够复杂,规划增加价值,或者 agent 在没有它的情况下已经可靠?
- 通过反思或批评使成本翻倍的质量门槛是什么?
- 我们如何确保 agent 的计划不仅是表演而是实际指导执行?

**注意事项**

- 计划可能错误,agent 应被允许偏离,而不是奴隶般遵循糟糕的计划
- 反思增加延迟,在实时用例中可能不可接受
- 自我纠正循环可以无限运行,总是限制重试

**要点总结: 规划、反思和自我纠正是 agentic 设计的廉价质量提升。当可靠性比成本或速度更重要时添加它们。**

**Qantas 案例**

反思和规划模式在 Qantas AI 用例中特别有价值,在那里出错的成本很高。以之前的中断恢复 agent 为例。天真的版本对每一步孤立反应,可能产生看起来合理但错过关键约束的恢复计划。添加规划和反思转变输出。

模式如下工作。当检测到中断时,agent 首先写一个结构化计划: "我将 (1) 识别所有受影响的航班和下游轮换,(2) 按影响分类每个航班,(3) 识别约束 (机组值勤、飞机可用性、时刻规则),(4) 为每个受影响航班提出恢复选项,(5) 根据约束验证每个选项,(6) 按总成本和客户影响对选项排名,(7) 生成恢复摘要。"计划对运营控制员在执行前可见。

然后 agent 通过计划工作。在每个主要步骤之后,反思 prompt 问"我是否解决了这一步要求的一切,以及我是否引入了与早期步骤的不一致"。反思是单独的模型调用,它增加延迟和成本,但它捕捉单次推理错过的错误。

最后,最终反思问"这个恢复计划在内部一致吗,它是否尊重所有约束,我会自信地将它呈现给值班经理吗"。如果反思识别问题,agent 在呈现之前修订。

这种纪律的成本是真实的。规划和反思大致使每任务的 LLM 成本翻倍。好处也是真实的。在像中断恢复这样的高风险情境中,从这些模式的质量提升是运营控制员信任的工具和他们忽略的工具之间的区别。信任是运营环境中 AI 采用的货币。

有趣的失败模式是性能表演,agent 写看起来彻底但实际上不塑造其行为的计划和反思。Agent 说"我将检查机组值勤时间限制",然后继续推荐违反它们的调换。防御是让计划和反思产生下游代码实际验证的结构化输出,而不仅仅是没有人阅读的自由形式文本。

对 AI 交付来说,启示是规划和反思是 agentic 设计的廉价质量提升。它们使成本翻倍,但经常在硬任务上使质量提升超过两倍。对客户的正确框架是将它们定位为草稿和审查草稿之间的区别,而不是花哨的 AI 模式。运营领导者理解审查工作的价值,这种框架比技术描述更快地建立信任。
