**Definition**

LLM providers charge per token, separately for input (what you send) and output (what the model generates). Output tokens are typically 3 to 5 times more expensive than input tokens. In agentic systems, every loop iteration adds the previous step's output to the next step's input, so costs compound quickly across steps.

**Why it matters in delivery**

Cost surprises kill more AI projects than quality problems. A team that does not model token costs early gets blindsided by a 10x bill in month two. PMs who understand the cost structure can scope honestly, design for affordability, and avoid the awkward conversation where the client asks why the demo cost USD 50 but production costs USD 50,000 per month.

**How it works**

| Cost component | Description | Typical ratio |
|---|---|---|
| Input tokens | System prompt + user message + retrieved context + tool definitions + history | 70 to 95 percent of token volume |
| Output tokens | Model response + tool call arguments | 5 to 30 percent of token volume |
| Output price multiplier | Output costs more per token | Usually 3x to 5x input price |
| Cached input | Some providers discount repeated input | 50 to 90 percent discount |

**Worked example, simple chat**

System prompt: 500 tokens. User message: 100 tokens. Retrieved context: 2,000 tokens. Total input: 2,600 tokens. Output: 300 tokens.

At sample pricing of USD 3 per million input, USD 15 per million output:

Input cost: 2,600 x USD 3 / 1,000,000 = USD 0.0078
Output cost: 300 x USD 15 / 1,000,000 = USD 0.0045
Total per call: USD 0.012

**Worked example, agent with 8 steps**

Each step appends the previous step's output to the next step's input. By step 8, the input includes everything that came before.

| Step | Input tokens | Output tokens | Step cost (USD) |
|---|---|---|---|
| 1 | 3,000 | 400 | 0.015 |
| 2 | 3,400 | 400 | 0.016 |
| 3 | 3,800 | 400 | 0.017 |
| 4 | 4,200 | 400 | 0.019 |
| 5 | 4,600 | 400 | 0.020 |
| 6 | 5,000 | 400 | 0.021 |
| 7 | 5,400 | 400 | 0.022 |
| 8 | 5,800 | 400 | 0.023 |
| Total | | | 0.153 |

A single agent task costs 12x a single chat call, not 8x, because input grows at each step.

**PM decision points**

- Have we modelled cost per task, not just cost per call?
- Are agent step counts and context growth measured in production, not just average tokens?
- Is output token usage being controlled, e.g. asking for concise output where possible?

**Watch outs**

- "Cost per token" headlines hide the real economics, output tokens dominate cost on generation heavy tasks
- Tool definitions count as input tokens on every call, fat tool schemas are silent cost drains
- Cached input savings only apply if prompts are structured to maximise cache hits, not automatic

**Takeaway: output tokens cost 3 to 5x input, and agents compound input every step. Model task cost end to end, not call cost.**

**Qantas story**

Token cost compounding shows up dramatically in any Qantas AI agent use case. Consider a hypothetical disruption recovery agent running through a complex scenario.

The agent starts with a system prompt of 3,000 tokens that describes its role, tools, and decision framework. The active disruption description adds 1,500 tokens. The first tool call retrieves flight schedule data, adding 4,000 tokens to the context. The second tool call retrieves crew availability, adding another 3,500 tokens. The third retrieves aircraft positioning, adding 2,000 tokens. By step four, the context is at 14,000 tokens before the agent has done much analysis.

Each subsequent step adds more. By step ten, the context might be 35,000 tokens, with the agent rereading and reasoning over all that accumulated information. Each step costs more than the previous one because the input is larger. The output for each step is typically a few hundred tokens of analysis plus a tool call, but the input dominates the cost.

The math is striking. A simple chat query might cost AUD 0.02 in total. A ten step agent task with the cost compounding described might cost AUD 0.80 or more. A twenty step agent task could easily cost AUD 3 or 4. The cost per task is not linear with steps, it is super linear.

The mitigation patterns are well known. Aggressive summarisation between steps reduces context growth. Older retrieved content can be replaced with summaries once the agent has used it. Tool call results can be condensed before being added to context. Periodically the agent can be asked to "summarise progress so far" and that summary becomes the working state, replacing the detailed history.

Another mitigation is structured state outside the context. Instead of keeping all data in the agent's context, the orchestration layer maintains a structured state object that the agent reads from and writes to selectively. The context contains the current focused subset of state, not everything.

The output side also matters. Asking the agent for concise outputs reduces output token cost. Asking for structured output (which is more efficient to generate than freeform) also helps. Asking for chain of thought in every step doubles or triples the output tokens for marginal quality gain.

For AI delivery, the lesson is that cost in agent systems needs to be modelled end to end, not per call. A team that scopes a project on cost per call will be off by an order of magnitude or more in agent use cases. The right framing for clients is "cost per task" or "cost per user per day," with realistic step counts and context growth modelled. Clients are often surprised by this because their mental model is per call cost, which is the wrong mental model for agents. Walking them through the actual math during scoping prevents surprises later.

**定义**

LLM 提供商按 token 收费。输入 tokens (您发送给模型的 prompt) 和输出 tokens (模型生成的内容) 单独定价,输出通常贵 3 到 5 倍。每个模型有它自己的费率,前沿模型比小型模型贵 5 到 50 倍。

**为何在交付中重要**

成本是大多数生产 AI 项目中最不被理解的维度。团队对最便宜模型的"每百万 tokens 几分钱"印象深刻,然后惊讶他们的月度账单是 4 万美元。理解 token 经济学是从合理的成本估算开始项目的方式,以避免预算事件。

**运作原理**

| 模型 (2026 价格) | 输入每 1M tokens | 输出每 1M tokens |
|---|---|---|
| Claude Haiku | $0.80 | $4.00 |
| Claude Sonnet | $3.00 | $15.00 |
| Claude Opus | $15.00 | $75.00 |
| GPT 4 nano | $0.10 | $0.40 |
| GPT 4 mid | $2.50 | $10.00 |
| GPT 4 large | $10.00 | $30.00 |
| Gemini Flash Lite | $0.04 | $0.30 |
| Gemini Pro | $2.50 | $10.00 |
| Llama 70B (Bedrock) | $0.99 | $0.99 |

(价格示意; 提供商定期调整)

一个 1,000 token 输入,400 token 输出请求:
- Claude Haiku: $0.0024
- Claude Sonnet: $0.009
- Claude Opus: $0.045

放大: 每天 100,000 个这样的调用:
- Claude Haiku: $240/天, $87,600/年
- Claude Sonnet: $900/天, $328,500/年
- Claude Opus: $4,500/天, $1,642,500/年

输出 tokens 的乘数是为什么响应长度重要。"用 200 个字回答"比"用 1,000 个字详细回答"便宜 5 倍。

**PM 决策点**

- 这个工作流每用户每月的平均 token 使用是什么?
- 高量用例是否在正确的模型层上?
- 我们如何控制输出 token 在不需要冗长的地方?

**注意事项**

- 在 LLM 调用中的检索文档计入输入 tokens,大文档贵
- 工具响应作为输入 tokens 返回到 LLM,显着累积
- "agent"的多轮 LLM 调用,累积成本数倍

**要点总结: Token 经济学是 AI 项目预算的核心。从第一天起为它建模,而不是当账单到达时。**

**Qantas 案例**

Qantas 设置中的 token 经济学迅速变得重要。考虑客户服务 AI 助手,在峰值期间每天处理 50,000 次互动。每次互动平均 4 轮。每轮使用约 2,000 输入 tokens (system prompt 加上下文加历史) 加上 400 输出 tokens。这是每个互动 8,000 输入 + 1,600 输出 tokens,跨 50,000 个互动每天。

每天: 4 亿输入 tokens, 8000 万输出 tokens。

每月: 120 亿输入 tokens, 24 亿输出 tokens。

成本按模型:
- 全 Claude Opus: $180K + $180K = 每月 $360K, 每年 $4.3M
- 全 Claude Sonnet: $36K + $36K = 每月 $72K, 每年 $864K
- 全 Claude Haiku: $9.6K + $9.6K = 每月 $19.2K, 每年 $230K

差异是巨大的。$4.3M 与 $230K 的成本差异是相同工作负载。客户服务能力的合理预算可能是每年 $300K 到 $500K。"使用旗舰模型为一切"使预算高出 10 倍。"使用最便宜的模型为一切"使预算正确,但可能在复杂查询上质量太低。正确的答案是混合: 简单查询去 Haiku,中等查询去 Sonnet,复杂查询去 Opus,用智能路由层。

这正是模型分层和路由 (前面讨论的) 在生产中重要的方式。$4.3M vs $300K 之间的差异不是关于模型质量。它是关于在工作流的每一步选择正确的模型。

更微妙的成本是输出 token 控制。"在 200 个字内回答" prompt 比未约束的 prompt 便宜 3 倍。在客户服务规模,简洁性指令削减数百万美元。客户经常想要详细的、彻底的响应,但客户实际上想要简洁的有用的响应。两者重合 (好的简洁响应) 并节省成本是企业 AI 中赢得它的简单优化之一。

第三个成本是检索成本。在 Qantas 内容上的 RAG 意味着每个查询检索文档块并将它们插入到 prompt 中。如果每个查询附加 4,000 tokens 的检索内容,这增加显著的输入 token 成本。优化检索 (使用较少但相关的块) 是真正的成本杠杆。

对 AI 交付来说,启示是 token 经济学不是工程关注的事后想法。它是项目的核心商业事实。能够在范围确定时为客户建模成本 ("这个用例每年将运行 200 到 400K,这里是为什么以及我们如何优化它") 的交付从业者展示他们将带到项目其余部分的纪律。客户欣赏成本透明度,因为它使 AI 投资可治理而不是不可预测。
