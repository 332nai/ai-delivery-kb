# 代码解释与审查

30 条 prompt: 解释不熟悉的代码、做代码审查。

## 解释代码

1. 用通俗语言逐行解释这段代码: [粘贴]。
2. 用 3 句话总结这个文件做什么: [粘贴]。
3. 用一个类比解释这个 [框架] 模式: [粘贴]。
4. 追踪数据如何在这些函数里流动: [粘贴]。
5. 解释 [语言] 中 [概念 A] 和 [概念 B] 的区别。
6. 为什么 [模式] 能解决 [问题]? 与朴素方案对比。
7. 一步步解释这行妙招式的一句代码: [粘贴]。
8. 把这段 [语言 A] 代码翻成 [语言 B],解释差异。
9. 逆向解读这段被压缩的代码做什么: [粘贴]。
10. 解释如果我从 [粘贴] 里删掉 [具体那行] 会怎样。

## 代码审查

11. 审查这个 PR diff,按严重度标出问题: [粘贴]。
12. 对这段代码做 bug、安全、性能三方面快速检查: [粘贴]。
13. 在 [粘贴] 里找出差一或边界错误。
14. 在 [粘贴] 里识别可能的 null/undefined 问题。
15. 检查这段代码里是否有竞态或共享状态 bug: [粘贴]。
16. 找出 [粘贴] 里的安全问题 (注入、XSS、密钥)。
17. 审视错误处理 — 异常是否被恰当捕获和记录? [粘贴]。
18. 识别死代码、不可达分支、未使用的引入: [粘贴]。
19. 检查命名一致性,建议重命名: [粘贴]。
20. 核对这段代码是否符合我们的风格指南 [粘贴指南]: [粘贴代码]。

## 架构与设计

21. 评判这个模块的设计 — 单一职责、耦合度: [粘贴]。
22. 为 [问题描述] 建议合适的设计模式。
23. 找出这个类违反 SOLID 的地方: [粘贴]。
24. 画出代码库依赖,标出循环依赖: [粘贴]。
25. 建议 [粘贴] 哪里需要引入抽象层。
26. 为 [系统描述] 对比微服务和单体的权衡。
27. 用 REST 原则评估这个 API 设计: [粘贴]。
28. 为 [应用描述] 建议状态管理方案。
29. 在 [粘贴代码库摘要] 里识别 3 个最大的技术债。
30. 为 [领域] 的 [N] 个实体推荐数据库 schema。
